# Security reporting

Please report suspected vulnerabilities privately using [Report a vulnerability](https://github.com/qoopia/qoopia-source/security/advisories/new). Do not open a public issue with an exploit, credentials or personal data.

Include the affected version and platform, the expected access boundary, a minimal reproduction using synthetic data, and the impact. Redact keys, cookies, database contents and private conversations. Do not test against another person's installation or the production account service without permission.

The current maintained release is Qoopia V1. Experimental client support and pilot transport qualification are described in the README; they are not claims of completed testing. We will assess reports and coordinate a fix and disclosure, but do not promise a response time or a paid bounty.

The public repository contains source code, not user databases or production credentials. Publishing code does not grant access to any installation. If you accidentally expose a credential in your own report, revoke it with its issuer rather than relying on deleting the report.
