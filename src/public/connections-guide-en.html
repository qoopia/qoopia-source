Connect your memory.

Use your chosen computer or server as the home for your memory. Give each client its own revocable connection.

This release supports the tested Codex CLI, Claude Code, Claude Desktop and Claude Web combinations listed below. ChatGPT Web and Desktop are experimental: memory calls passed in an isolated prototype, but setup verification is not qualified. A saved configuration alone is not a successful connection.

Start with your workspace

  1. Open Qoopia. Confirm the workspace name and machine shown in the sidebar. If you already use a server, keep that server selected.
  2. Open Connections. Select the client and choose Read only or Read and add.
  3. For clients that connect from the cloud, enable External connection. Confirm your Qoopia account by email or Google and return to Continue setup. You do not need a domain, router change or tunnel-provider account.
  4. Prepare the connection, then follow the client's steps below. Qoopia shows the exact address. During OAuth, check the workspace, client and permissions before allowing access.
  5. Choose Get verification prompt, run that prompt inside the selected client, and check status in Qoopia. The prompt expires after ten minutes; obtain a fresh one if needed.

Claude Code

Add the entry with the same Qoopia button or setup file. Open Claude Code, run /mcp, select the Qoopia connection and authenticate. Then run the verification prompt. The client entry has its own URL; other MCP settings and model credentials are preserved.

ChatGPT Web — experimental

Claude Web

Open Customize → Connectors → + → Add custom connector. Paste the prepared URL, add it, choose Connect and complete OAuth. Enable it in a conversation, then run the verification prompt. Free permits one custom connector; Team and Enterprise require an organization owner to add it.

Claude Desktop

On a Mac, choose Add to client on this computer, then Open consent page. For memory on another machine, download the setup file and open it with Qoopia on your Mac. Review the selected workspace and permissions in your browser. Return to Qoopia and check status, restart Claude Desktop, then run the verification prompt in a new conversation. The local adapter stores its OAuth credentials privately, outside Claude’s configuration, and follows the installed Qoopia version after updates. Linux installations can prepare a setup file for a Mac. Claude Desktop 1.52386.3 on macOS has passed real memory calls, token refresh, file import and reading after a full restart.
The separate remote connector path is under Customize → Connectors. It requires a reachable external address because requests originate from Anthropic’s cloud.

Continue after an interruption

Your prepared connections remain in this workspace. Reopen Connections and check status. A sleeping, offline or powered-off machine cannot answer; it has not lost its memory. The service reconnects when the machine is awake and online. An interrupted write should be retried only with the same idempotency key and unchanged input.

“Client call verified” is a record of the last successful call. External connection health is shown separately. If sign-in expires, restart that sign-in; keep the prepared connection. For a client on another computer, use that server's external address.

Control access

Read and add allows reading memory and creating new records. It does not grant editing or deleting existing notes. Those tools are unavailable to this connection.

Use Revoke access for one client, or pause external access for the installation. Revocation does not delete memory. Cloudflare processes authorized traffic in transit and terminates HTTPS; no end-to-end encryption is claimed. The account service holds account and device metadata, not a copy of your memory database.

MCP gives a client tools to read or write allowed memory. It does not automatically capture the entire conversation. The background model's subscription login is a separate flow in Memory model settings.

Tested client combinations

Observed on 12 September 2026 with existing ChatGPT Pro and Claude Max subscriptions. Other plans, operating systems and client versions are not qualified by these results. Each row is a separate client test.

  • Codex CLI 0.153.3, Linux x64: OAuth, verification, reading, adding and duplicate protection passed; reading after update, sleep and reboot passed.
  • Claude Code 2.1.224, Linux x64: the same memory sequence and reading after reboot passed.
  • Claude Desktop 1.52386.3, macOS Apple Silicon: local adapter, OAuth, memory sequence, natural token refresh and file import passed; reading after network interruption and reboot passed.
  • Claude Web: remote OAuth, verification, reading, adding and duplicate protection passed against a clean Mac installation.
  • ChatGPT Web: OAuth, reading, adding and duplicate protection passed in the isolated synthetic prototype. The client blocked the verification call; this surface is not fully accepted.
  • ChatGPT Desktop: manual reading, adding and duplicate protection passed in a ChatGPT conversation on macOS. The synthetic database independently contained one new note. These prototype results do not qualify the complete setup flow for this release.

Physical macOS sleep and wake passed with the signed V14 local installation: the same process, note and pre-sleep settings survived. This is local recovery evidence, separate from native-client and network tests. The guest VM refused sleep; network interruption and reboot passed separately.

Installation and local files

The packages target macOS Apple Silicon and Linux x64. On Linux, extract the archive, open its folder, and launch Open Qoopia. The separate open-qoopia.sh file is a terminal alternative; some file managers open shell scripts in an editor. Both packages are publisher-signed; the macOS package has passed Apple notarization. Clean-system installation and updates have been tested. Only the client combinations identified as supported above are within this release’s qualification. On macOS, open a .qoopia-connection file with Qoopia and review the address before adding it. Linux CLI import uses qoopia client-link --file /absolute/file.qoopia-connection, followed by --commit --approve PLAN_DIGEST from the displayed plan. No configuration editing is needed. This setup file contains a URL and permissions, not a token.

The separate connections-agent.md file shipped with the bundle documents agent setup and stable status codes.
