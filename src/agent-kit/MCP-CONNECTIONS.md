# Подключение и восстановление MCP

## Штатный путь

Открой Connections в дашборде выбранной установки или установленный `qoopia connections`. Прочитай `qoopia help` и `connections-agent.md` именно этого пакета. Не подставляй демонстрационный или разработческий адрес вместо памяти пользователя.

Сначала план: JSON selection содержит surface (`chatgpt_web`, `chatgpt_desktop`, `claude_web`, `claude_desktop`, `codex`, `claude_code`, `muse_code`, `muse_app`, `grok_bot`), access_mode (`read` или `read_write`) и стабильный request_key. transport — auto/local/remote по контексту. Команды: `connections plan --input ABSOLUTE_JSON`, затем разрешённый `connections apply --input ABSOLUTE_JSON --commit`. Используй возвращённые ID и точный MCP URL, не собирай их по догадке. Muse Code настраивается в пользовательском settings.json и входит через `muse mcp login`; облачный Grok Bot получает точный удалённый MCP URL в запросе на добавление коннектора. Наличие записи или OAuth не доказывает работу: вызови `qoopia_protocol` из выбранного клиента после OAuth. Сервер автоматически подтверждает первое успешное чтение протокола через точное подключение клиента. Автосохранение сессий для этих клиентов отдельно пока не настроено.

Для облачного клиента нужна доступная снаружи установка. Штатный network-plan/network-start/network-resume проводит регистрацию и пользовательский вход. Подготовь метод email/google согласно текущей схеме. Сервис/туннель должен работать; localhost на Mac не доступен Claude.ai или ChatGPT в облаке.

## Разные клиенты

- Codex: client-plan/client-apply или client-link готовят отдельную запись в выбранном CODEX_HOME/config.toml. Сохрани остальные серверы и модель. Пользователь авторизует именно эту запись; затем новая сессия читает AGENTS.md либо действующий AGENTS.override.md. В управляемом блоке есть ссылка на qoopia-protocol.md.
- Claude Code: используй выбранный CLAUDE_CONFIG_DIR, штатный конфиг и /mcp для входа. CLAUDE.md импортирует qoopia-protocol.md. Не путай пользовательский профиль с .mcp.json произвольного проекта. Для автоматического сохранения сессий используй memory-link и его штатные hooks, а не копирование чужих hook-файлов.
- Claude Desktop: штатный локальный adapter/client-auth на macOS, затем перезапуск приложения. Удаление записи из JSON не отзывает OAuth grant. Приложение не обязано читать локальный CLAUDE.md: получи протокол через MCP qoopia_protocol и при необходимости добавь его в инструкции выбранного проекта.
- Claude.ai: настрой разрешённый пользователю remote MCP connector в интерфейсе Claude, пройди пользовательский OAuth к точному подготовленному URL. Локальные AGENTS.md/CLAUDE.md в браузер сами не попадут. Протокол доступен инструментом qoopia_protocol; закрепи инструкцию прочитать его в выбранном проекте/разговоре, если эта функция есть у клиента.
- ChatGPT Web/Desktop: используй доступный в аккаунте официальный интерфейс apps/connectors/developer mode для custom MCP. Возможности зависят от клиента, плана и политик организации; если интерфейс отсутствует или проверка блокируется клиентом, зафиксируй BLOCKED. Последняя проверка с настоящим клиентом (ChatGPT Pro, Web и Desktop на Mac) прошла 15 сентября 2026 года; текущие согласие и автоматическое подтверждение подключения с настоящим аккаунтом ChatGPT повторно не проверялись. Не обходи клиентский запрет другой поверхностью и не называй Codex-задачу проверкой ChatGPT-чата. Прочитай qoopia_protocol через выбранный connector; для постоянного поведения закрепи протокол в доступных инструкциях проекта. Локальный файл не считается автоматически установленным в облачный аккаунт.

## Проверка и переподключение

1. Сначала connections status/resume для существующего ID. Используй готовый запрос из карточки подключения; он не содержит временного кода.
2. Из выбранного клиента вызови qoopia_protocol через его точный MCP URL. После успешного вызова сервер подтверждает подключение, дашборд обновляет статус автоматически. Настройка, OAuth и tools/list сами по себе не подтверждают работу. Для совместимости оставлена отдельная verify-операция с одноразовым challenge; обычному пользователю она не нужна.
3. При обычном истечении входа повторно авторизуй существующее подключение; не создавай лишнего агента. SIGN_IN_REQUIRED при network registration требует нового network-start и пользовательского согласия.
4. При CLIENT_CONFIG_MISSING используй client-plan/client-apply. При CLIENT_CONFIG_CHANGED/CONFLICT сохрани пользовательскую правку; не перезаписывай конфиг. Сначала согласуй восстановление конкретной записи.
5. Отозванное подключение нельзя оживлять правкой токена/SQL. Создай новое с новым request_key после выбора прежнего workspace и нужного scope; проверь его реальным вызовом. Старую локальную запись удаляй только штатным client-remove с receipt. Не удаляй другие MCP.
6. Если переносится профиль, явно выбери config_directory/--config-directory. Ранее сохранённая привязка должна указывать на тот же профиль. Не правь native_root вручную и не копируй OAuth/хуки между профилями. Повторный memory-link того же сервера после перевыпуска агента или смены ключа заменяет прежнюю привязку (хуки, запись `qoopia_memory`, файл подключения) с резервными копиями; изменённую вручную запись он не трогает.
7. Отказ локальных инструкций (код `INSTRUCTIONS_*` и путь файла в `protocol`) не мешает записи MCP: протокол доступен через qoopia_protocol. Исправь указанный файл и повтори client-apply или memory-link. Удалённый вручную блок Qoopia хук и `instructions refresh` не возвращают; его добавит только явный client-apply или memory-link.
8. Отключение без ручных правок: `memory-unlink --runtime codex|claude_code --commit` убирает хуки memory-link, запись `qoopia_memory` с ключом и управляемый блок; `instructions remove --runtime codex|claude_code --commit` убирает блок и неизменённые документы. Без `--commit` это только план. Чужие хуки, серверы и текст владельца сохраняются, изменённое отклоняется. Отзыв агента в Qoopia — отдельное действие.
9. Проверь протокол в новой сессии: агент должен назвать источник инструкции и её версию. Проверь read; проверку записи выполняй только с разрешённым тестовым содержимым. При read scope запись не требуется и не разрешается.

Обновление инструкции не меняет MCP scopes, не выдаёт владельческую роль и не считается успешным подключением. Сохрани отчёт по отдельности: config installed, user authenticated, protocol available/loaded, MCP verified, memory read/write, session capture/summary/restore.


## Онбординг стюардом: подготовить и довести до реального вызова

- Сначала проверь актуальный `qoopia_capabilities` и существующую идентичность. Не переименовывай FIBI в Phoebe и не создавай дубль уже подключённого агента.
- Если доступен `connection_prepare`, передай точные `agent_name`, `surface`, `access_mode`. Для исправления подписи существующего подключения передай его `connection_id`. Это чтение: инструмент не создаёт ключей, агентов или OAuth grants. Верни владельцу одну ссылку `owner_url`, а не JSON-инструкцию.
- Владелец открывает подготовленную форму, проверяет имя, приложение и права и нажимает «Подготовить подключение». Параметры ссылки не подтверждают согласие и не выдают доступ. Приложению передаётся точный MCP URL из этой записи. Для действующего подключения форма открывает его карточку: «Сохранить имя» сохраняет ID, OAuth, ноты и подтверждение; классификацию можно исправить только между Muse.app и Muse Code CLI.
- `muse_app` — облачный агент в Muse.app (например FIBI); приложение Mac — интерфейс, а не место исполнения. `muse_code` — отдельный терминальный клиент. Команды `muse mcp login` и его `settings.json` не настраивают Muse.app.
- Для Muse.app используй «Скопировать запрос»: он включает настройку и чтение протокола через тот же MCP URL, без временного проверочного кода. Используй поддерживаемый MCP-клиент облачного рантайма. Наличие встроенного экрана произвольного MCP не обещай: оно требует отдельной проверки. Если безопасного OAuth-пути в клиенте нет, назови именно это препятствие; не предлагай сломанный localhost callback с копированием кода в чат. Секреты и OAuth-коды в переписку не передаются.
- Получи протокол и capabilities из самого целевого клиента. Запрос должен указывать точный MCP URL выбранного подключения. Для read_write отдельно проверь разрешённую синтетическую запись, чтение и повтор с тем же idempotency key. MCP-доступ и автосохранение всей переписки проверяются отдельно.
- Если инструмент подготовки отсутствует, прочитай актуальный раздел connections через `qoopia_protocol`; не выдавай ещё не установленный инструмент за доступный. Сохрани цель и точный существующий ID для штатной формы владельца, не повышай собственные права.

В том же браузере действующая сессия владельца используется для OAuth-согласия без повторного письма. Согласие на права каждого нового клиента остаётся явным. Если сессии владельца нет, потребуется обычный вход. Другой аккаунт, агентская сессия и OAuth-токен агента не заменяют сессию владельца.
