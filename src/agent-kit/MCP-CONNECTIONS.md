# Подключение и восстановление MCP

## Штатный путь

Открой Connections в дашборде выбранной установки или установленный `qoopia connections`. Прочитай `qoopia help` и `connections-agent.md` именно этого пакета. Не подставляй демонстрационный или разработческий адрес вместо памяти пользователя.

Сначала план: JSON selection содержит surface (`chatgpt_web`, `chatgpt_desktop`, `claude_web`, `claude_desktop`, `codex`, `claude_code`, `muse_code`, `grok_bot`), access_mode (`read` или `read_write`) и стабильный request_key. transport — auto/local/remote по контексту. Команды: `connections plan --input ABSOLUTE_JSON`, затем разрешённый `connections apply --input ABSOLUTE_JSON --commit`. Используй возвращённые ID и точный MCP URL, не собирай их по догадке. Muse Code настраивается в пользовательском settings.json и входит через `muse mcp login`; облачный Grok Bot получает точный удалённый MCP URL в запросе на добавление коннектора. Наличие записи или OAuth не доказывает работу: заверши реальным вызовом `connection_verify` из выбранного клиента. Автосохранение сессий для этих клиентов отдельно пока не настроено.

Для облачного клиента нужна доступная снаружи установка. Штатный network-plan/network-start/network-resume проводит регистрацию и пользовательский вход. Подготовь метод email/google согласно текущей схеме. Сервис/туннель должен работать; localhost на Mac не доступен Claude.ai или ChatGPT в облаке.

## Разные клиенты

- Codex: client-plan/client-apply или client-link готовят отдельную запись в выбранном CODEX_HOME/config.toml. Сохрани остальные серверы и модель. Пользователь авторизует именно эту запись; затем новая сессия читает AGENTS.md либо действующий AGENTS.override.md. В управляемом блоке есть ссылка на qoopia-protocol.md.
- Claude Code: используй выбранный CLAUDE_CONFIG_DIR, штатный конфиг и /mcp для входа. CLAUDE.md импортирует qoopia-protocol.md. Не путай пользовательский профиль с .mcp.json произвольного проекта. Для автоматического сохранения сессий используй memory-link и его штатные hooks, а не копирование чужих hook-файлов.
- Claude Desktop: штатный локальный adapter/client-auth на macOS, затем перезапуск приложения. Удаление записи из JSON не отзывает OAuth grant. Приложение не обязано читать локальный CLAUDE.md: получи протокол через MCP qoopia_protocol и при необходимости добавь его в инструкции выбранного проекта.
- Claude.ai: настрой разрешённый пользователю remote MCP connector в интерфейсе Claude, пройди пользовательский OAuth к точному подготовленному URL. Локальные AGENTS.md/CLAUDE.md в браузер сами не попадут. Протокол доступен инструментом qoopia_protocol; закрепи инструкцию прочитать его в выбранном проекте/разговоре, если эта функция есть у клиента.
- ChatGPT Web/Desktop: используй доступный в аккаунте официальный интерфейс apps/connectors/developer mode для custom MCP. Возможности зависят от клиента, плана и политик организации; если интерфейс отсутствует или проверка блокируется клиентом, зафиксируй BLOCKED. В Qoopia эти поверхности остаются experimental до полной квалификации. Не обходи клиентский запрет другой поверхностью и не называй Codex-задачу проверкой ChatGPT-чата. Прочитай qoopia_protocol через выбранный connector; для постоянного поведения закрепи протокол в доступных инструкциях проекта. Локальный файл не считается автоматически установленным в облачный аккаунт.

## Проверка и переподключение

1. Сначала connections status/resume для существующего ID. Получи свежий verification prompt через штатную verify-операцию.
2. Из выбранного клиента вызови qoopia_protocol, затем connection_verify с выданными ID и challenge. Challenge краткоживущий; запроси новый при истечении. Настройка или OAuth не дают права выставить verified.
3. При обычном истечении входа повторно авторизуй существующее подключение; не создавай лишнего агента. SIGN_IN_REQUIRED при network registration требует нового network-start и пользовательского согласия.
4. При CLIENT_CONFIG_MISSING используй client-plan/client-apply. При CLIENT_CONFIG_CHANGED/CONFLICT сохрани пользовательскую правку; не перезаписывай конфиг. Сначала согласуй восстановление конкретной записи.
5. Отозванное подключение нельзя оживлять правкой токена/SQL. Создай новое с новым request_key после выбора прежнего workspace и нужного scope; проверь его реальным вызовом. Старую локальную запись удаляй только штатным client-remove с receipt. Не удаляй другие MCP.
6. Если переносится профиль, явно выбери config_directory/--config-directory. Ранее сохранённая привязка должна указывать на тот же профиль. Не правь native_root вручную и не копируй OAuth/хуки между профилями.
7. Проверь протокол в новой сессии: агент должен назвать источник инструкции и её версию. Проверь read; проверку записи выполняй только с разрешённым тестовым содержимым. При read scope запись не требуется и не разрешается.

Обновление инструкции не меняет MCP scopes, не выдаёт владельческую роль и не считается успешным подключением. Сохрани отчёт по отдельности: config installed, user authenticated, protocol available/loaded, MCP verified, memory read/write, session capture/summary/restore.
